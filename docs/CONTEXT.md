## 3. 소유자 요구사항 정리

### 반드시 (MUST)
1. **끌어서 스크랩**이 핵심 상호작용이다. 페이지의 요소를 그냥 잡고 끌어서 콜라주에 놓는다. ("쉽게 이것저것 끌어서")
2. **상용 사이트에서 실제로 동작**해야 한다. (옛 버전은 대부분의 상용 사이트에서 못 씀 → 이게 리빌드의 이유)
3. 가져온 조각은 **원본과 같은 모양**이어야 한다. (옛 README: "가져온 조각이 원본과 똑같아 보여야" + 가독성 높은 문서 재구성이 목적)
4. 동작이 **엉성하지 않아야** 한다. (체험판 수준 탈피)

### 하지 말 것 (소유자가 명시적으로 거부)
- ❌ **클릭으로 담기를 주된 방식으로 만드는 것.** 소유자 원문: "클릭하면 의미가 없어". (보조 수단으로 덧붙이는 것도 소유자 확인 없이 하지 말 것)

### 옛 프로젝트에서 이어갈 정신
- "필요한 정보만 골라 재구성해서 가독성을 높인다" (옛 README의 출발점: 정보가 혼잡한 공식 문서를 내 방식대로 재구성)
- Box & Block 구조(박스 = 바구니, 블록 = 개별 조각), 가로/세로 정렬, 테마(다크 모드 등), 마우스를 올리면 하이라이트되는 직관적인 UX

## 4. 이 대화에서 확정된 것 / 아직 안 정한 것

| 구분 | 내용 |
|---|---|
| ✅ 확정 | 다시 받아오기 방식 폐기, 실제 탭에서 캡처 |
| ✅ 확정 | 편집기는 크롬 사이드 패널 |
| ✅ 확정 | 드래그는 브라우저 기본 드래그(HTML5 DnD), 번호표(id)만 싣고 스냅샷은 따로 전달 |
| ✅ 확정 | 스냅샷 = 계산된 스타일을 요소마다 인라인으로 굳히기 (검증에서 실제 사이트 원본과 거의 동일) |
| ✅ 검증됨 | 위 방식이 Linux Chromium 141에서 실제 마우스로 동작 |
| ⏳ 미검증 | **Windows/Mac 크롬**에서 동일하게 동작하는지 (OS 드래그 처리 경로가 다름) → 소유자가 집 PC에서 확인 예정 |
| ❓ 미정 | 새 레포로 갈지 기존 레포를 이어 쓸지, 공유/협업 기능 시점, 백엔드 선택 → [`PLAN.md`의 "착수 전 결정 사항"](PLAN.md#13-착수-전-결정-사항) |
